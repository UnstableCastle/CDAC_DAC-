3. Priority process scheduling algorithm 

		every process has a priority assigned to it
		Generally the priority is a number between 1 to 10 
		1 = lowest  10 = highest priority
		Who decides the priority of the process ? 
		  kernel proces gets higher priority compared to user process.
		  some user processes get higher priority than other user processes based on which user starts the process
		  programatically processes can set their own priority using system calls
			
	Technique  = cpu schedular will select the process with highest priority amongst the processes in ready queue .	
			
	Non preemptive priority = a process running currently can run for its CPU-burst-time .

    Preemptive Priority  = If a process with higher priority than currently running process arrives in ready queue then the current process will be preempted by the new process	
	
	Advantage - priority of the process is considered
	Disadvantage - Starvation of low priority process may happen
				
			TO overcome starvation = AGEING technique is used
			If a process is not gettting cpu for a threshold time then the process is promoted to next priority

RR = Round Robin Scheduling Algorithm 

    Time slice = time quantum  = small time duration after which a TIMER interrupt occurs and the running process is preempted .

	
	technique = select the process that is in the front of the queue .
	
	Preemtive  =  after every time quantum the process using the cpu is preempted and next process runs 
	
	Advantage  = Improves the Response time  by giving an effect of Multitasking 
	
    Disadvantage =
	
		1. Each process waits every time after time quantum 
			- Avg Wt is more , Avg Tat is high , throughput is low
    	2.  Heavy context switching overhead 		
	  
	
    Context = snapshot of the CPU registers at a given point of time 
    context switching = save the last snapshot before leaving the CPU and load the snapshot before resuming on cpu 	
	
		time quantum = 2ms
	  
	process      arrivaltime      CPU-burst-time
	  P1               0				4
	  P2               1                5
	  P3               2                3
	  
	  Use RR to compute the avt Tat and Wt

Queue  Scheduling Algorithm 

		Multilevel Queues are created based on the Priority 
		
		technique = till the high priority queue is not empty the low priority queue is not executed 
		the processes in one queue are executed using FCFS 
		
		Disadvantage = Starvation in low priority queues 
						solution = Ageing

Orphan Process = Child process whose parent has terminated before the child's termination . this orphan process is adopted by process 1 of the kernel .  


What happens if the parent process terminates before child process ? 
	1. child process becomes orphan 
	2. the resources of a child process are released by parent process after child termination . However if parent terminates before child  and child terminates later then the resources of the child are not released but child process is over - called as ZOMBIE state - unnecessary memory allocation .
	3. IDEALLY  the parent should wait for the child to terminate and only after that the parent should terminate .
		for this a system call = waitpid is used 
		
	 waitpid will block the parent code and prevent parent termination till the child is alive .
	 after child changes state to terminate then waitpid unblocks and allows the parent to finish
