Interrupt

   Who interrupts Whom ? 
   
   There are interrupt pins on the CPU receive the interrupt signals 
   the signals are sent by hardware like kbd,mouse, harddisk ,printer once an action is completed 
   
  What happens when interrupt signals arrive at CPU ? 
  The Interrupt Handler is EXECUTED/RUN 
  and the currently running process is HALTED
  
  ------------------------------
  Interrupt handler is a pre written function of the OS 
  For some interrupts we can change the handler , for some we cannot 
	- Maskable and Non Maskable interrupts 
	
	+  whether Timer interrupt is Maskable or not 
---------------------------------
	The handlers are maintained in a table 
	Interrupt Table / Interrupt Vector Table 
	
	  InterruptNumber |  Ptr to Handler
	     1					 fun1
		 2                   fun2 
		 ...
		 
	Kernel will find the interrupt number occuring at the CPU and accordingly run the Interrupt handler mapped to it in the interrupt handler

Every process has a life cycle - created and terminated 

Following phases/states of process life cycle ?
    1.created/born
	2.ready
	3.Running/executing
	4.IO wait/suspend
	5.Terminate 
	
created/born phase of process 
	1. process gets a PCB= Process Control Block 
			PCB has process Info  like pid, priority, status
	2. process gets a address space 
			process space in RAM 
			for ex - a c process gets space for 
			 for parts - code segment , data segment, stack segment, heap segment 
			this is c process address space !!
			Java process space = JVM = class area, stack area, heap area  


ready phase/state = the process is ready for execution so it is waiting for the CPU in a ready queue in kernel space 

Running/executing phase/state = the process gets the CPU and it is running the CPU instructions of the process

IO Wait state/suspended phase/state = the next instruction of the process is IO instruction so the process leaves the cPU and the DMA runs the IO instruction - meanwhile process waits for IO to complete 

Terminate state = the process reaches the end of execution code so it terminates the kernel will now release the PID ,PCB , address space and other resources of the process .

Process Scheduling/cpu scheduling/low level scheduling

cpu-Schedular/low-level-schedular/schedular of the Kernel  will
 
  Select a process from ready queue 
   and then
  allocate the process to the cPU


Parameters that must be improved - schedular keeps these parameters in mind while selecting next process to run on cpu !!!

1. CPU-burst-time = Total time taken by all cpu-instructions in one process is called as CPU-burst-time of that process.

2. IO-burst-time= Total time taken by all io-instructions in one process is called as io-burst-time of that process.

3. Average Wait Time  = Wt
    Wait time = total time spent by the process in the ready queue is the Wait time of the process
	
	Average Wait Time = (Wt1 + Wt2 + Wt3+...+Wtn)/n
	
	Good Avg Time is as small as possible !!!
	
4. Average Turnaround time = Ta 
	  Turnaround time = the total time spent by the process from create to terminate excluding IO wait-time 
	  
	  Average T A T  = (Ta1 + Ta2 +Ta3+...+Tan)/n
	  
	  Ta = Wt + CPUt 
	     = Wait time  + CPU-burst-time
	  
	  Good Average Tat will be as small as possible 
	  
5. Response time  = the time taken by the process to respond to the user 

   Good response time should be as small as possible 
   
6.  Througput of the system = It is the number of processes completed in unit time 
		processes compeleted per sec
	
	Good throughput should be as high as possible 



Common basic Process Scheduling Algorithms = these are the techniques used by the schedular to select a proces from the ready queue for running on cpu 

1.FCFS
2.Shortest Job First 
3.Priority
4.RR = round robin 
5.Queue 


1. Name of scheduling algorithm= FCFS = First come First serve
   
   Technique = The process that is in the front of the ready queue is selected for running on cpu 
   
   Non Preemptive algorithm = process can use the cpu for its CPU-burst-time and then leave the cpu 
   
   Advantage = simple , non preemptive 
   Disadvantage = The process after the current process has to wait for the CPU-burst-time of the current process, if it is more then a smaller process has to wait for long time . Ta of small processes becomes HIGH . Average Ta increases , Throughput decreases . CONVOY EFFECT .
   
   Process     ArrivalTime      CPU-burst-time
     P1          0                  5ms
	 P2          1                  3ms
	 P3          4                  4ms
	 P4          3                  1ms 
	 
	Find the average Wt and Tat  using FCFS for above data 
	
	 Wait time =  Start time - arrival time

		 Wt2 =   5 - 1 = 4
		 Wt3 =   9 - 4 = 5 
		 Wt4 =   8 - 3=  5 
		 
		 Average Wt = (0+4+5+5)/4 = 3.5 
		 
	  Turnaround Time =  Wait time + CPU-burst-time
	         Ta1 =  0 + 5 = 5 
			 Ta2 =  4 + 3 = 7

2. Shortest Job First = (SJF ) 

      Technique = Select the process that has smallest cpu-burst-time.
	  
	  
	  Non Preemptive SJF = It can use the CPU for its CPU-burst-time
	  
	  Preemptive SJF = It can use the CPU till a new smaller cpu-burst-time process arrives in ready queue 
	  
time_remaining_of_current_process > cpu-burst-time_of new_arrival
	  
	  PREEMPTION Happens = current process returns to ready queue and new process runs on the CPU 
	  
	  
	  Advantage of SJF =  No CONVOY Effect because smaller process gets selected first so average Wt is small
	  average Tat small throughtput high 
	  
	  Disadvantage = 
	   We cannot predict the cpu-burst-time beforehand 
	   theoretical algorithm 
	   
	   Starvation of high cpu burst time process
