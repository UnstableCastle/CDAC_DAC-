------------------------------------------------------------
1. VIRTUALIZATION
------------------------------------------------------------

Definition:
Virtualization allows multiple Virtual Machines (VMs) to run on a
single physical machine using a Hypervisor.

Architecture:

+----------------------+
| Applications         |
+----------------------+
| Guest OS             |
+----------------------+
| Hypervisor           |
+----------------------+
| Host Operating System|
+----------------------+
| Physical Hardware    |
+----------------------+

Disadvantages:
- Heavyweight
- Requires Guest OS for every VM
- High RAM and CPU usage
- Large storage requirement
- Slow boot time

------------------------------------------------------------
2. DOCKER
------------------------------------------------------------

Definition:
Docker is an open-source containerization platform that packages an
application along with all its dependencies into a Container.

Architecture:

+----------------------+
| Application          |
+----------------------+
| Container            |
+----------------------+
| Docker Engine        |
+----------------------+
| Host Operating System|
+----------------------+
| Hardware             |
+----------------------+

Docker replaces:
- Hypervisor
- Guest Operating System

------------------------------------------------------------
3. CONTAINER
------------------------------------------------------------

A Container is a lightweight isolated environment that contains:

- Application
- Libraries
- Dependencies
- Runtime

Containers DO NOT contain a complete Operating System.

------------------------------------------------------------
4. VIRTUAL MACHINE vs DOCKER
------------------------------------------------------------

Virtual Machine
---------------
- Uses Hypervisor
- Separate Guest OS
- Heavy
- Slow Startup
- High RAM
- Large Storage

Docker
------
- Uses Docker Engine
- Shares Host OS
- Lightweight
- Fast Startup
- Less RAM
- Small Image Size

------------------------------------------------------------
5. ADVANTAGES OF DOCKER
------------------------------------------------------------

* Lightweight
* Fast Startup
* Application Isolation
* Secure
* Portable
* Easy Deployment
* Easy Scaling
* Less Storage
* High Performance

11. WHY KUBERNETES?
------------------------------------------------------------

Docker can manage few containers.

Example:

10 Containers      -> Easy
100 Containers     -> Manageable
10000 Containers   -> Difficult

Need Kubernetes.

------------------------------------------------------------
12. KUBERNETES
------------------------------------------------------------

Definition:

Kubernetes is an open-source Container Orchestration Platform.

Functions:
- Deployment
- Scaling
- Monitoring
- Networking
- Load Balancing
- Self Healing

------------------------------------------------------------
13. FEATURES OF KUBERNETES
------------------------------------------------------------

* Auto Deployment
* Auto Scaling
* Self Healing
* Load Balancing
* High Availability
* Rolling Updates
* Rollback
* Storage Management

------------------------------------------------------------

------------------------------------------------------------

                 MASTER NODE

 +--------------------------------------+
 | API Server                           |
 | ETCD                                |
 | Scheduler                           |
 | Controller Manager                  |
 +--------------------------------------+

               WORKER NODE

 +--------------------------------------+
 | Kubelet                             |
 | Kube Proxy                          |
 | Pods                                |
 | Containers                          |
 +--------------------------------------+

------------------------------------------------------------
15. MASTER NODE COMPONENTS
------------------------------------------------------------

API Server
----------
- Entry Point
- Accepts Requests
- Communicates with Components

ETCD
----
- Distributed Key-Value Database
- Stores Cluster Information

Scheduler
---------
- Assigns Pods to Worker Nodes

Controller Manager
------------------
- Maintains Desired State
- Recreates Failed Pods

------------------------------------------------------------
16. WORKER NODE COMPONENTS
------------------------------------------------------------

Kubelet
--------
- Node Agent
- Starts Containers
- Stops Containers
- Reports Node Status

Kube Proxy
----------
- Networking
- Service Communication
- Load Balancing

Pods
----
Smallest Deployable Unit in Kubernetes.

------------------------------------------------------------
17. SELF HEALING
------------------------------------------------------------

If a Container crashes,

Kubernetes automatically:
- Restarts it
- Replaces it
- Maintains Desired State

------------------------------------------------------------
18. LOAD BALANCING
------------------------------------------------------------

              Users
                |
        Load Balancer
      /      |       \
     C1      C2      C3

Traffic is distributed equally.

------------------------------------------------------------
19. AUTO SCALING
------------------------------------------------------------

High Traffic

Traffic ↑
Pods ↑

Low Traffic

Traffic ↓
Pods ↓

------------------------------------------------------------
20. HIGH AVAILABILITY
------------------------------------------------------------

Application continues running even if:

- Pod fails
- Node fails
- Server fails

21. DOCKER vs KUBERNETES
